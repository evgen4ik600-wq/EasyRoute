# 🚀 EasyRoute

**Простая выборочная маршрутизация через AmneziaWG на OpenWrt.**

Выбираете сервисы и устройства — EasyRoute отправляет только их через нужный VPN. Остальной трафик продолжает идти напрямую через WAN.

[![EasyRoute CI](https://github.com/evgen4ik600-wq/EasyRoute/actions/workflows/ci.yml/badge.svg)](https://github.com/evgen4ik600-wq/EasyRoute/actions/workflows/ci.yml)

> YouTube через VPN, банки и обычный интернет напрямую — без ручного nftables, fwmark и таблиц маршрутизации.

---

## Что это такое

EasyRoute — LuCI-интерфейс и набор системных скриптов для OpenWrt, который упрощает policy-based routing через **AmneziaWG**.

Он не запускает отдельный VPN-движок и не прячет туннели внутри себя. EasyRoute использует обычные интерфейсы AmneziaWG, уже существующие в OpenWrt, и поверх них строит маршрутизацию.

Схема простая:

```text
Клиенты
   │
   ▼
OpenWrt
   │
   ├── обычный трафик ───────────────► WAN
   │
   └── выбранные сервисы/устройства
                    │
                    ▼
              nftables / fwmark
                    │
                    ▼
              routing table
                    │
                    ▼
               AmneziaWG
```

---

## Что умеет

- 🧩 **Каталог OpenCCK Main + Beta** — поиск, категории и выбор нужных сервисов.
- 🌐 **Маршрутизация по доменам** через `dnsmasq-full + nftset`.
- 📦 **IPv4 CIDR по желанию** — отключены по умолчанию, потому что некоторые списки могут содержать слишком широкие сети.
- 🛡️ **Несколько AmneziaWG-интерфейсов** — `AWG`, `AWG_2`, `AWG_3` и далее обнаруживаются автоматически.
- 🔀 Для каждого правила можно выбрать, **через какой AWG его отправлять**.
- 📱 Можно направить **целое устройство по MAC-адресу** через выбранный VPN.
- 🔄 URL- и каталожные списки автоматически проверяются и обновляются.
- 🚦 Режим fallback: вернуть трафик в WAN или заблокировать его, если VPN недоступен.
- 🩺 Встроенная самодиагностика: Internet / VPN / firewall / DNS / routing / updater / OpenCCK.
- 🌐 Совместная работа с уже установленным `https-dns-proxy` / локальным защищённым DNS.
- 🔐 Опциональный DNS-over-TLS через Stubby, если другого защищённого DNS нет.
- ↩️ Rollback, если новая конфигурация не проходит проверку.
- 🔥 Проверка `fw4` до окончательного применения сетевых изменений.
- 🧪 Встроенный read-only аудит `easyroute-audit`.

## Пример

Допустим, на роутере есть два туннеля:

```text
AWG    → сервер №1
AWG_2  → сервер №2
```

В EasyRoute можно сделать:

```text
YouTube      → AWG
ChatGPT      → AWG
Telegram     → AWG_2
Телевизор    → AWG_2
Банки        → WAN
Остальное    → WAN
```

Никаких ручных `ip rule`, nft sets и отдельных routing tables вводить не нужно.

## Поддержка нескольких AWG

EasyRoute автоматически ищет интерфейсы:

```text
network.*.proto='amneziawg'
```

После импорта нового туннеля в стандартном OpenWrt он появляется в EasyRoute автоматически.

Для каждого профиля выделяются отдельные `fwmark` и routing table. Перед использованием EasyRoute проверяет, что выбранные policy-routing slots не заняты другой программой.

Если AWG-интерфейс был удалён, EasyRoute **не переключает связанные правила молча на другой VPN**. В интерфейсе такой профиль отмечается как отсутствующий и требует внимания.

## Каталог OpenCCK

Каталог загружается только при открытии окна выбора и не хранится целиком во flash.

Используются:

- основной каталог OpenCCK;
- Beta-каталог OpenCCK.

После выбора сервисов на роутер сохраняются только необходимые списки.

По умолчанию EasyRoute загружает **домены**. Опция **«Добавлять IPv4 CIDR»** включается отдельно.

Почему CIDR выключены по умолчанию: некоторые агрегированные сервисы могут содержать очень широкие диапазоны адресов. В таком случае через VPN может уйти трафик, который пользователь не собирался туда отправлять.

---

## Требования

Рекомендуемая конфигурация:

- OpenWrt **24.10.x** или **25.12.x**;
- LuCI;
- firewall4 / nftables;
- `dnsmasq-full` с nftset;
- AmneziaWG 3.1 или совместимый системный AmneziaWG;
- доступ в интернет во время установки.

Установщик поддерживает OpenWrt с `apk` и `opkg`.

> Совместимость AmneziaWG зависит от архитектуры роутера, ядра и конкретной сборки OpenWrt. Если для устройства нет совместимого kmod/пакета AmneziaWG, EasyRoute это исправить не сможет.

## Установка

Подключитесь к роутеру по SSH под `root` и выполните:

```sh
wget -qO- "https://raw.githubusercontent.com/evgen4ik600-wq/EasyRoute/main/install.sh?$(date +%s)" | sh
```

После установки:

```text
LuCI → Сеть → 🚀 EasyRoute
```

Если AmneziaWG ещё не настроен, сначала создайте или импортируйте AWG-интерфейс в стандартном разделе:

```text
LuCI → Сеть → Интерфейсы
```

После поднятия интерфейса EasyRoute обнаружит его автоматически.

---

## После чистого сброса OpenWrt

Типичный сценарий:

1. Сбросить именно **OpenWrt** к заводским настройкам.
2. Настроить WAN и убедиться, что у роутера есть интернет.
3. Запустить команду установки EasyRoute.
4. Импортировать конфигурацию AmneziaWG в OpenWrt.
5. Открыть EasyRoute и выбрать нужные сервисы.

То есть в обычном случае:

```text
чистый OpenWrt
    ↓
одна команда установки
    ↓
импорт AWG
    ↓
выбор сервисов
    ↓
готово
```

## Автообновление списков

Cron запускает проверку URL-списков каждый час.

Само правило по умолчанию обновляется не чаще одного раза в 24 часа. Если загрузка завершилась ошибкой, используется более короткий retry-интервал.

Новый список сначала скачивается во временный файл. Если после него EasyRoute не может корректно применить firewall/routing, предыдущая версия списка восстанавливается.

---

## DNS

EasyRoute использует `dnsmasq` для доменной маршрутизации.

Если на роутере уже есть локальный защищённый DNS, например:

- `https-dns-proxy`;
- `dnscrypt-proxy`;
- другой localhost DNS forwarder,

EasyRoute не должен перезаписывать его.

Если защищённого DNS нет, можно включить Stubby/DoT с одним из провайдеров:

- AdGuard DNS;
- Cloudflare;
- Google.

---

## Fallback

Если выбранный VPN недоступен, доступны два режима:

**WAN** — трафик временно продолжит идти напрямую.

**BLOCK** — трафик, назначенный на недоступный VPN, будет блокироваться.

BLOCK удобен там, где утечка трафика в обычный WAN нежелательна.

## Диагностика

В интерфейсе есть кнопка общей проверки.

Для подробного read-only аудита из SSH:

```sh
/usr/libexec/easyroute-audit
```

Аудит проверяет:

- RPC;
- AmneziaWG;
- handshake;
- policy routing;
- nftables / fw4;
- dnsmasq;
- OpenCCK Main + Beta;
- updater;
- cron;
- locks;
- текущие правила.

Секретные AWG-ключи в отчёте редактируются.

---

## Безопасность и защита от конфликтов

EasyRoute старается не вмешиваться в чужую сетевую конфигурацию.

В частности:

- не заменяет `/etc/config/network`;
- не удаляет AmneziaWG при удалении EasyRoute;
- не заменяет пользовательский firewall целиком;
- использует собственные nftables-файлы;
- проверяет `fw4` перед применением;
- проверяет конфликты `ip rule` и routing tables;
- не очищает routing table, если она используется другим policy-routing правилом;
- сериализует сетевые операции lock-файлами;
- сохраняет предыдущие конфиги/списки перед опасными изменениями;
- делает rollback после неуспешного apply.

---

## Что проверяется CI

GitHub Actions запускает:

- shell syntax;
- ShellCheck critical errors;
- JSON validation;
- синтаксис LuCI JavaScript;
- проверку installer references;
- архитектурные инварианты EasyRoute;
- rollback-инварианты;
- multi-AWG discovery;
- routing-table collision protection;
- OpenCCK wiring;
- DNS coexistence;
- защиту временных файлов и locks.

CI не заменяет тестирование реальной сети, поэтому важные сетевые изменения дополнительно проверяются на настоящем OpenWrt-роутере.

## Удаление

```sh
wget -qO- "https://raw.githubusercontent.com/evgen4ik600-wq/EasyRoute/main/uninstall.sh?$(date +%s)" | sh
```

EasyRoute удаляет свои LuCI/RPC/nftables/cron-компоненты и policy routes.

Пользовательские списки и backup в `/etc/easyroute` намеренно остаются для возможного восстановления.

## Ограничения

Сейчас это не универсальный PBR-пакет для любого возможного OpenWrt.

Основная целевая конфигурация — современный OpenWrt с firewall4/nftables и AmneziaWG.

Также важно:

- доменная маршрутизация работает, когда клиент использует DNS роутера;
- клиентский DoH/Private DNS может обходить dnsmasq и мешать доменной классификации;
- IPv4 CIDR могут быть слишком широкими — включайте их осознанно;
- автоматическое обнаружение AWG не означает автоматическое создание самого VPN-конфига.

## Статус проекта

**Активная разработка.**

Текущая ветка содержит автоматическое multi-AWG discovery, динамический каталог OpenCCK, rollback и встроенную диагностику.

Проект уже используется и тестируется на реальном OpenWrt, но перед экспериментами с маршрутизацией всё равно разумно иметь локальный доступ к роутеру и backup конфигурации.

## Для кого это

EasyRoute делается для людей, которым нравится OpenWrt, но не хочется каждый раз руками собирать:

```text
dnsmasq nftset
→ nftables
→ fwmark
→ ip rule
→ routing table
→ AmneziaWG
```

Если хочется просто отметить нужные сервисы и выбрать VPN — это именно тот сценарий, который EasyRoute пытается сделать нормальным.
